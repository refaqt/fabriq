# 2026-10-07 — Locks on FreeCAD files

**Role(s):** software

## What happened

fabriq now locks a FreeCAD file with Git LFS as soon as someone changes it, also before
they save. A colleague who opens the same file sees a red warning in fabriq. The lock goes
when the pull request merges. Before this, two people could change the same file, and the
second change could not be merged.

Work done:

- A small layer over `git lfs` to take, list and release locks.
- The lock keeper: it watches the changed files and the open FreeCAD window, takes the
  locks, and warns about the colleagues' locks.
- Change sets keep their locks until the merge, and refuse a push on a file a colleague
  holds.
- The Git page lists the locked files, with an Unlock button for your own. The workspace
  page shows the warning.

## Decisions

- [ADR-002 — Lock a FreeCAD file as soon as it changes](../decisions/2026-10-07_lfs-locks.md)

## Checked

- New tests run against real git repositories with a fake lock server: a changed file is
  locked, unsaved changes are locked, a colleague's lock gives a warning, and the lock goes
  after the merge. All 22 backend tests and the frontend build and tests pass.
- Not tested with a real FreeCAD window or the GitHub lock server.

## Next Steps
